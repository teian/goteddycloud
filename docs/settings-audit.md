# Settings behavior audit

Reference: 78c3b38e36f665d3a5fffe907f73a02725176377. The generated inventory retains every macro entry, including duplicate UI tree nodes. `compatibility-audit.json` attaches a behavior classification and evidence to every settings, CLI, routing and integration row. Route evidence remains in `compatibility-evidence.json`. These classifications do not establish device acceptance.

Every schema setting participates in defaults, API indexing, typed validation, global/overlay lookup and flat-file preservation. `internal/config/store_test.go` exercises persistence, isolation, invalid writes and unknown fields; the offline oracle compares the settings index. Consumer classifications are:

- Listener addresses, configured directories, certificate material, box identity and access flags are consumed by startup, confined storage, certificate loading and identity resolution. Prefix-based certificate consumers cover the complete TB1/TB2/client groups.
- Cloud flags, upstream targets, content metadata policy, caches and local OTA use the device/cloud services. The configured HTTP client timeout controls cloud TCP and TLS connection establishment, with an independent 30-second operation deadline and response-header limits. Other public downloads have separate fixed limits.
- Audio and stream settings control bitrate, buffer, restart, skip and maximum length. TAP caches always receive full integrity validation in Go, including when `core.tap_taf_validation=false`; this is an intentional stronger check. Track-position failures do not trigger C's additional diagnostic-only SHA1 pass; invalid track mappings are rejected by the existing parser. `core.full_taf_validation` controls ordinary indexed content validation.
- Security mitigation updates transient global incident state and enforces configured locking. Domain hashes and crawler strings are source-derived. Develop checks crawler and domain detection independently; the older master else-if behavior is superseded. Robots access is recorded even when its file is absent. The first robots request can complete; subsequent requests can be locked. The local executable replay observes C locking plain HTTP with `httpsOnly=true`; Go applies that flag to TLS connections. Go persists settings immediately, so hardLock enabled by a successful write takes effect on the next request; C can delay it while configuration is dirty.
- CORS sets the configured Access-Control-Allow-Origin response header. Like C, this setting alone does not add an authenticated session or a new preflight API.
- Official metadata updates run at startup when enabled, in a cancellable worker, and retain previous validated files on failure. Both tonies.json and tonieboxes.json use the fixed public source, system TLS trust and no device credentials. Synthetic fixtures disable startup updates. Updates are asynchronous in Go; C blocks its startup loop while fetching. Docker readiness testing cancels startup work instead of waiting for public metadata downloads.
- Frontend.*, encode.use_frontend, core.file_upload_timeout_ms and debug.web.pcm_encode_console_url are frontend configuration values. Backend persistence/indexing is implemented; their frontend interaction acceptance remains pending. The pinned C source declares toniebox2.baby_mode and toniebox2.lightring_brightness without consuming them in its MQTT settings response; Go preserves that behavior rather than inventing commands. MQTT disable_on_error also continues retrying in C; Go retains retries.
- MQTT/HA settings control external connection, credentials, topics, discovery, QoS and embedded TLS endpoint. Discovery and embedded settings responses have executable C comparisons. See verification.md for bounds and explicitly stronger validation.
- Catalog settings control image caching/preload and custom-backup retention. RTNL settings control raw and CSV append logs. PCAP and TLS-key settings enable separate private, bounded diagnostics described below.

Logging differences: Go uses structured slog text and does not reproduce C's colored trace formatting, full-token logging or individual C trace messages. `log.color` and `log.logFullAuth` are preserved configuration values without those side effects. Log severity is selected by `log.level`; fatal process-startup errors remain visible. Go does not emit device authentication tokens into normal logs.

Internal-state differences: native C pointer/cache fields and build metadata are retained as schema/API values, not copied into Go memory representations. Config writes are atomic and immediate; C's dirty/save-cycle fields are not a save queue. Internal certificate buffers are not populated with private material merely to reproduce an API diagnostic. Runtime firmware fields, RTNL state, box generation and security incident state have explicit consumers. Remaining C internal counters/version/process-state fields retain their default or persisted values unless updated by a named Go consumer; these rows are documented deviations, not assertions of live-state parity. `configVersion` is preserved without C's historical version-specific configuration migrations; copied deployments must pass validation.

Diagnostics differences: opt-in PCAP captures application requests/responses at the Go handler boundary in raw IPv4/TCP records, with valid IP/TCP checksums and a 64 MiB file cap. It includes bodies and credentials supplied to those endpoints; it is off by default. It omits C's synthetic SYN/FIN packets, outbound HTTP/cloud traffic, transport retransmission and implicit unread request bodies. Box captures use the private backend endpoint addresses; IPv6 is represented as loopback IPv4. TLS key logs cover web and box server handshakes, cap at 4 MiB, and omit outbound-client/MQTT secrets. Both outputs are confined inside the deployment, private mode 0600, append on restart, and stop recording at their cap without interrupting traffic. C permits arbitrary filenames and unbounded logs. Parser/checksum, stream-flush, cap, confinement and actual executable restart checks use disposable synthetic traffic and identities only.
